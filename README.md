# SQL Data Quality Lab

Учебный проект XNova: синтетический интернет-магазин для самостоятельной практики SQL. Достаточно Python 3.12: база работает через встроенный `sqlite3`, без сервера, Docker, сети и аккаунта GitHub. Работает после скачивания ZIP или клонирования репозитория.

## Быстрый старт

Распакуйте ZIP и откройте терминал в корне проекта либо клонируйте репозиторий. На Windows при необходимости используйте `py -3.12` вместо `python`.

```bash
python -I scripts/init_db.py --output .work/shop.sqlite
python -I scripts/check.py --smoke
python -I scripts/check.py --task joins
python -I scripts/check.py --final
```

Первая команда создаёт базу для свободного исследования; повторный запуск создаёт её заново. `--smoke` проверяет исходные таблицы и всегда проходит на неизменённом проекте. Задания и финал в исходном состоянии закономерно не проходят: исправляйте SQL в `queries/`. Порядок работы — в [tasks/README.md](tasks/README.md). Проверяющий сам создаёт временные базы, поэтому изменять `.work/shop.sqlite` для сдачи не требуется.

## Выполняем произвольные SQL-запросы

После создания `.work/shop.sqlite` вы можете запускать свои `SELECT` без Python-скриптов. Из корня проекта выполните:

```bash
python -m sqlite3 .work/shop.sqlite "SELECT * FROM orders LIMIT 5;"
```

Чтобы последовательно вводить несколько запросов, откройте интерактивный интерфейс:

```bash
python -m sqlite3 .work/shop.sqlite
```

Введите, например, `SELECT order_id, order_status FROM orders WHERE order_id = 107;` и нажмите Enter. Введите `.quit`, чтобы выйти; `.help` покажет доступные команды. SQL-запрос завершается точкой с запятой, а служебная команда с точкой (`.quit`) — без неё. Этот интерфейс встроен в **Python 3.12 и новее**. На Windows вместо `python` при необходимости используйте `py -3.12`. Для стабильного порядка строк добавляйте `ORDER BY`.

В упражнениях используйте только `SELECT`. Если случайно изменили учебную базу, снова запустите `python -I scripts/init_db.py --output .work/shop.sqlite`: команда восстановит исходные данные. Скрипт проверки `check.py` создаёт собственные временные базы и не использует изменения в `.work/shop.sqlite`.

## Модель и правила денег

`users` содержит покупателей; `orders` — заказы; `order_items` — позиции; `payments` — события платежей; `shipments` — доставки. Ключ каждого объекта указан в `data/schema.sql`. Один заказ может иметь несколько позиций, событий платежей и доставок или не иметь их вовсе. Все суммы хранятся целыми копейками.

- `order_amount_cents` = сумма `quantity * unit_price_cents` по позициям заказа, 0 без позиций.
- `paid_amount_cents` = сумма успешных платежей (`status = 'successful'`) по уникальным `transaction_ref` внутри заказа. Повторный импорт той же успешной транзакции с той же суммой учитывается один раз. Разные успешные транзакции одинаковой суммы учитываются отдельно. Противоречивые суммы у одного ключа — ошибка данных.
- `unpaid_amount_cents` = стоимость заказа минус успешные платежи. Отрицательная разница допустима. Это учебные показатели заказа и полученной оплаты, а не бухгалтерская выручка.

Отчёт содержит все заказы, включая заказы без позиций и оплат, ровно по одной строке на заказ. Итоговый `final_report.sql` также выводит `order_status`; статус не фильтрует строки. Доставки не меняют денежные показатели.

## Проверки

```bash
python -I scripts/check.py --task amounts
python -I scripts/check.py --task payments
python -I scripts/check.py --task reconcile
python -I scripts/check.py --final
```

Проверки выполняют ваш SQL и сверяют каждую строку с независимым подсчётом исходных позиций и платежей. Они повторяют запрос на изменённых данных: дополнительной доставке, повторе импорта, неуспешной попытке, другом количестве позиции, равной стоимости разных позиций и новом пустом заказе. При ошибке показывают конкретный заказ и поле. Для разработки самого стенда: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest -q tests`; pytest не нужен студенту для выполнения заданий.
